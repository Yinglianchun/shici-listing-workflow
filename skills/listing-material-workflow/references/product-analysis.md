# 开始前的本品分析

没有商品信息时先追问本品ASIN/链接或标题、五点、参数，以及主推子体；只有ASIN/链接先自行尝试读取，失败再请求资料。缺关键参数、事实冲突或变体归属不清时，明确列出具体问题，请用户补充确认。未确认前相关判断留待确认，不猜补、不直接判不存在，不先写肯定答案；不受缺口影响的机械整理或已知部分可以继续。

可只提供ASIN或商品链接，由agent先自行查看本品页并记录来源、读取时间与当前子体，再补缺失资料；不先要求用户复制完整页面。检查可读的主图、附图、尺寸图及A+图片，页面文字读取不能代替图片核对。文字读完后主动反问：“除了已读取的文字，图片里还有没有未补充的参数、卖点、使用说明或子体差异？”图片读不到时请用户补图/转述，记录未读范围；新信息注明图片来源、ASIN及子体，冲突先确认口径。

从完整标题、五点、参数、本型号A+及用户明确确认内容，提炼定位、核心卖点、适用人群和场景。每条附对应原文，并可说明回应了什么买家关注点；不从竞品、AI拓词Evidence或品类常识补事实。商品页已有定位和普通用途可以保留，不额外要求独立研究。

先读完用户已提供的全部五点，主动问尚缺的现有QA、A+问答/副标题、图片说明，以及“页面没写但实物已有”的卖点。问清对应ASIN/子体与部件，用户确认后记录原话和来源、更新完整资料，并提示商品页需补的内容；未回复的记临时state.json，不生成待补表、不当作产品没有。用途也含穿搭、派对、购物、社交和拍照，不限于功能活动。

Listing 优化优先独立分析本品，由已确认的款式、颜色、材质、用途及可读的本品图找页面还没说清的使用方式。AI 原问用于补查关注点；原问缺少某主题时，也可以从本品依据提出页面建议。适合穿搭的商品应写出具体单品或组合，例如已确认复古椭圆款可建议搭牛仔夹克和白T，而不是只写“百搭”。将搭配写为建议，标注所依据的本品特征及适用子体；不同配色的搭配按已确认子体分别记录。把适合的建议填入“共用场景清单”及对应的“五点修改建议”或“需同步的页面字段”，写清建议放在哪和为什么。只有在相关资料支持时才提穿搭，不强行给每种产品安排搭配，不由款式推导性能。原问未覆盖时关联QA可留空，不补造原问；建议不自动进入09长描述。

本品明确五点/参数、本型号QA/A+、用户明确确认内容共同组成依据；相互冲突时列原话待统一，不用AI拓词Evidence、竞品说明或品牌泛称覆盖本型号信息。AI原问只提供可能的关注方向，不能据其数量断言真实需求、搜索量或重要性。

**00事实基准为03的必需输入，不得只用分析摘要代替。** 在“本品完整资料”原样记录每段本品资料后，从原文及已确认补充提取可核验的属性记录：目标ASIN、父子体/配色、部件（镜框/镜片/鼻梁/鼻托/镜腿/铰链等）、属性、具体值、单位、原文片段、文件/页面/图片位置、确认状态。数值同单位或换算后比较时记录换算；区分鼻梁宽与鼻托宽、镜腿长与镜框宽、镜片宽高；不同子体颜色不得混用。图片与五点不一致时保留双方原文、来源并标注待统一，不从竞品Evidence推测哪个对。将事实记录写入现有本品资料/依据/差异工作表，过程记录存00步骤备份，不另建第五份Excel。03开始时必须读取这份基准，不能只看标题摘要或拓词输出。

## 店铺共用的已确认资料

以下三条为用户确认的本店眼镜共用卖点，适用于本店所有眼镜款式和子体。换款或换子体直接沿用，无需重复确认。00分析将它们写入本品资料表，03适用性和07 QA/A+直接引用，来源写“用户确认的店铺共用资料”。

- **镜框汗液腐蚀、发绿或皮肤过敏**：本品镜框采用24小时防汗液腐蚀电镀，另有防过敏设计。遇到出汗后金属腐蚀或发绿的问题，说明电镀的抗汗液腐蚀用途；遇到皮肤过敏的问题，说明防过敏设计。两种问题可合答，仍分别说明两项属性，不把电镀本身当作防过敏依据。24小时对应抗汗液腐蚀，不是佩戴时长或不过敏保证。
- **镜片防刮**：本品镜片具有防刮性能。英文名词为 `scratch resistance`，修饰镜片写 `scratch-resistant lenses`。涉及是否易刮时说明镜片防刮，不写 `scratchproof`。
- **UV400是否会脱落**：本品的UV400防护内置在镜片中，不会像表面涂层那样剥落。可答 `UV400 protection is built into the lenses, so it won't peel off.` 不推断具体制造工艺或镜片受损后的防护表现。

## 单款已确认的补充资料

本次讨论的偏光款镜片为9层，来源写“用户确认的本品补充”。遇到问偏光与UV防护的QA可用这一细节。此条按单款沿用。

本店另有已确认的长期佩戴、皮肤接触或过敏相关卖点时，按具体款式补记。有相关原问时优先挑1—2个QA方向。

本品资料表保留本品分析（类别、要点、原文依据、关注点）与资料差异（字段、原文一、原文二、差异、建议）。缺失信息在当前步骤直接向用户集中询问，不另建待补资料Sheet；未答问题与关联ID只记临时state.json。资料差异中分“冲突”与“口径待统一”，保留两段对应原文；程序分别保存conflicts与pending_unification。空表可留空，不制造冲突凑表。完整原文仍在本品资料表“本品完整资料”与程序已有的product.json，不用摘要替代。

区分三类：两段原文确实不一致、定位或适配口径需要统一、资料尚缺。用户写在待确认里的疑问并非已经成立的冲突。集中提出关键问题，其他已知部分照常继续；用户确认新卖点后同步完整资料，并提示页面是否需要更新。

眼镜例子：140mm框宽不能直接推翻小脸定位，但标题“小/窄脸”和五点“中小椭圆脸”的口径可列待统一；非偏光与页面列日常驾驶用途不构成文字矛盾；UV防护和偏光分别核对。镜框形状不同于适配脸型，框色不同于镜片色，套戴近视镜不同于自带矫正度数。例子不为其他商品预设参数。
